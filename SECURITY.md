# Security policy

## Supported versions

The reference artifacts are drafts. No version is represented as a
production-supported security product or security control.

## Reporting a concern

Do not include vulnerabilities, secrets, personal information, customer information, proprietary code, or production evidence in a public issue.

Use the repository's
[private vulnerability reporting form](https://github.com/ZeroUITechnologies/software-change-governance-reference/security/advisories/new)
to submit a confidential security advisory. If that option is temporarily
unavailable, do not disclose sensitive details in a public issue. Use the
form at https://www.zeroui.dev/demo/ and begin the message with “Security
report” to request a private reporting channel without including the sensitive
report itself.

The repository owner should enable, test, and monitor GitHub private
vulnerability reporting as part of publication setup. No response-time service
level is promised by this draft policy.

## Relevant concerns

Security reports may include:

- a schema design that encourages unsafe embedding of sensitive evidence;
- ambiguity that could cause an authorization or accountability field to be misinterpreted;
- malicious or unsafe sample data;
- workflow or validation weaknesses; or
- accidental disclosure in repository history.

The reference artifacts themselves do not constitute a security control, a compliance control, or a warranty of product security.
